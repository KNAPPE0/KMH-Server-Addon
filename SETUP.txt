Colony Nexus server addon (KMH Server Addon) - setup
====================================================

Extract this zip into your server folder, next to the RWT server:

    your-server-folder\
        GameServer.exe        <- the official RimWorld Together server
                                 (named RTServer.exe on newer RWT builds)
        KMHServerAddon.exe     <- this (run it)
        KMH-Data\              <- created on first boot; the zip seeds its Icons
        Tools\                 <- get-media-tools, if you want in-game video

Then run KMHServerAddon.exe (NOT the RWT server).

There are two downloads per platform, and which one you took decides what is in
the zip:

  KMH-ColonyNexus-ServerAddon-v1.3.1-<platform>.zip
    One KMHServerAddon.exe with everything inside it. Needs .NET 10 on the host.

  KMH-ColonyNexus-ServerAddon-v1.3.1-<platform>-selfcontained.zip
    Carries .NET 10 with it, so nothing to install - but it is a folder of files,
    and KMHServerAddon.exe is only a small launcher that will not start without
    them. Extract the whole thing and keep it together.

Either way it works with the RWT server you put next to it, adds the Colony Nexus
features, and starts the server. It detects which server version it sits next to
and uses the matching build automatically, identifying that server by what the
file actually contains rather than by its name - so a renamed or panel-mangled
server file is still found.

RWT releases for this version:
  26.10.20.1 - a RimWorld 1.7 server
  26.10.15.1 - a RimWorld 1.6 server
RWT moved a core network type below 26.5.24.1, so 26.4.18.1 and older are a
different generation - on those Colony Nexus refuses to start and says so,
leaving RWT running.

On RWT 26.6.23.1 and newer, RWT chat is not a reliable Colony Nexus carrier -
keep the Colony Nexus API transport enabled (the default since v1.2.0); it's the
recommended/required path there.
On first run it creates KMH-Data/ (configs + state), kmh-extensions/, and a
small .rwt-runtime/ cache next to itself.

Requirement
-----------
The .NET 10 runtime installed on the server:
    https://dotnet.microsoft.com/download/dotnet/10.0
Keep it patched: 10.0.13 or newer, and each .NET 10 security release after it. The
runtime also runs RWT's server, and it is what answers the network. .NET 10 is a
long-term release, supported until November 2028. The -selfcontained zips carry 10.0.13.
(Colony Nexus patches RWT with Harmony, which needs the JIT from a normally-installed
runtime - it can't reach the one baked inside the self-contained GameServer.exe.
That's the one thing the owner installs once.)

If no RWT server is in the folder, Colony Nexus says so and stops. It prints every file
name it looked for, which one it picked, and why it skipped the others - so a
"not found" is always explainable.

After an RWT update Colony Nexus re-reads the server automatically; its .rwt-runtime/
cache is keyed to the exact server file, so a stale cache can't survive an
upgrade. Deleting .rwt-runtime/ is always safe - it is rebuilt on next start.

Updating to 1.3.1
-----------------
Update EVERY player's Colony Nexus mod (KMH: Colony Nexus) to 1.3.1 alongside the
server. This release moves the wire protocol from v2 to v3, and unlike the
1.2.x -> 1.3.0 step that is a HARD BREAK: a 1.3.0-or-older client connecting to a
1.3.1 server shows its own (older) message

    KMH version mismatch. This server requires KMH Protocol v3; your client is
    using Protocol v2. Update KMH-Patch to match the server.

and Colony Nexus stays off for that session. The same happens in reverse.

That is the point of the bump. v1.3.1 changes when enforcement happens, who
decides mod settings, and how a config apply commits - behaviour a v2 client
cannot take part in, but which it would have looked perfectly healthy ignoring.
An old client that silently misses half a release is worse than one that says so.

Plan for it: update the server and tell players to update the mod at the same
time. If Config Enforcement is ON, an out-of-date client is disconnected with
that message rather than admitted; with Enforcement off it can still play RWT
normally, just without Colony Nexus.

Back up KMH-Data before the first 1.3.1 boot (the server also auto-backs-up on
boot by default) and run 'kmh validate all' afterward.

Your tunable configs are REGENERATED from the v1.3.1 defaults on that first boot,
not carried forward - every value you set in Economy, Sites, World, Chat, Media,
Mail and the rest is replaced. The originals are copied first into a
'premigration-config' folder under KMH-Data-Backups, verified, and the upgrade
refuses to run at all if that copy cannot be made. Global.json, Staff.json and
Discord/DiscordConfig.json are never regenerated. Afterwards, re-apply the tuning
you still want from that backup; 'kmh config' shows what differs from the
defaults. Later 1.3.1 builds only top files up with new fields - rel-267 also
renames one World.json key (the quest activity window, now in minutes) and
carries your value across.

Four version numbers, deliberately separate - don't read one from another:
  Public version        1.3.1        what the release is called
  Build tag             rel-NNN      the exact binary, for a bug report
  Wire protocol         v3           which clients this server talks to
  RWT compatibility     its own list (above) - unrelated to all three

No .NET 10 on your host, or no internet on it to go and get one? Managed panels
often pin an older runtime. Grab the "-selfcontained" zip for your platform
instead - it carries .NET 10 inside it, so there is nothing to install and
nothing to download on the server itself. Every architecture has one:
win-x64, win-x86, win-arm64, linux-x64, linux-arm and linux-arm64.

Either way, extract the WHOLE folder and run the exe from inside it. The normal
build is a single executable with its dependencies inside it, but it still ships
KMH-Data alongside (icons and notes), and the "-selfcontained" build also lays
the whole .NET runtime beside the exe. Copy only the executable out of the
folder and you lose those files.

On Linux the file is named KMHServerAddon with no extension, and a zip cannot
carry the execute bit, so make it runnable once after extracting:
    chmod +x KMHServerAddon
    ./KMHServerAddon
Without that first line the host reports "Permission denied" and nothing starts.

Managed / panel hosts (Bisect, Pterodactyl, etc.)
-------------------------------------------------
These run a fixed launcher (usually GameServer.exe) every start, so they never
run KMHServerAddon.exe. Two ways to fix it:

  - If the panel lets you edit the start command, point it at
    KMHServerAddon.exe. Done - survives RWT updates.

  - If the start button is locked to GameServer.exe, swap KMH into that slot
    (KMH detects the real server under a renamed name and boots it):
        rename  GameServer.exe      ->  GameServer.rwt
        rename  KMHServerAddon.exe   ->  GameServer.exe
    Linux (no .exe):  GameServer -> GameServer.rwt ,  KMHServerAddon -> GameServer
    (then: chmod +x GameServer)
    If your RWT server file is named RTServer instead, rename that one:
        RTServer.exe -> RTServer.rwt.exe   (Linux: RTServer -> RTServer.rwt)
    KMH never mistakes itself for the server - it checks what each file
    contains, not what it is called or how big it is - so the swap is safe.
    Redo the two renames after any RWT update - it restores the stock launcher.
    On a host without .NET 10, use the -selfcontained zip for this.

Stopping: KMH starts itself a second time with ReadyToRun off, and that second
process is the server. Stop the one you started - from the panel, Task Manager
or 'docker stop' - and the server follows it out, writing KMH's data on the way.
On Linux, a stop signal sent to the server process itself (systemd's default
sends one to every process in the service) ends it without that final write.
Run 'kmh save' first - in systemd, as the unit's ExecStop - so the last minutes
of chat and stats are kept.

KMH API transport - security & public setup
-------------------------------------------
ON by default since v1.2.0 (Config/Transport.json EnableKmhApiTransport=true,
BindAddress=0.0.0.0) - the recommended transport path for newer RWT versions.
Do not enable unsafe transport exposure. Public KMH API Transport is allowed by
default only because auth, caps, throttling, limits, and warnings are required
by default. Public bind must not mean unsecured bind.

Public setup (remote players):
  1. Forward TCP port 5099 (KmhApiPort) to the server machine, external =
     internal port number.
  2. Keep RequireKmhApiAuth=true. Every connection authenticates with a one-time
     token issued over the player's verified RWT session.
  3. After updating, run `kmh transport-test` - it self-checks the caps,
     throttle and posture and prints PASS/FAIL per guard.
Local-only instead? Set BindAddress=127.0.0.1. Chat fallback keeps KMH working
either way on RWT versions that still carry it.

Required-by-default safety (all clamped so a bad edit can't disable a guard):
RequireKmhApiAuth, and in Transport.json's Advanced block MaxConnections,
MaxConnectionsPerIp, AuthTimeoutSeconds, IdleTimeoutSeconds, MaxFrameKb,
FailedAuthPerIp/WindowSeconds/BlockSeconds. If you disable auth or expose the
port unsafely the server prints a loud warning at boot - public bind + auth off
is never a silent setup.

Multiple servers on one host: give each KMH instance its OWN KmhApiPort in its
KMH-Data/Config/Transport.json (like each RWT server has its own port). The server
tells the client its port in the handshake, so the client always dials the right
one - just as a player joins RWT 25554-25557, KMH connects to that server's KMH
API port. Two instances sharing a port = the second fails to bind, and it then
tells clients the transport is off rather than sending them at a port it never
opened; `kmh status` reads "ENABLED but not bound". For remote players, forward
each KmhApiPort (keep external = internal port number).

Players never type a port. The number you set in KmhApiPort is the number the
server hands out, so the one thing that has to be true is that you forwarded THAT
port. If you forwarded a different one, change KmhApiPort to match it and restart
- do not ask players to change anything. `kmh status` prints the exact host and
port clients are being told to dial, which is the fastest way to confirm the two
agree. The client's own "fallback port" setting is used only for a server that
advertises none at all.

Client debug uplink (diagnosing player-side issues)
---------------------------------------------------
A player who shares their KMH log has every line from their game land in
KMH-Data/Debug/<user>_<timestamp>.txt (one file per player session, every line
arrival-timestamped). The player decides, never the server: in the mod options
they pick Never, Ask me each server, or Automatically share. Setting
DebugLogging=true in Config/Transport.json only ASKS connecting clients to share -
a player on Ask sees a prompt for that session, a player on Never is not asked,
and nothing is sent without that choice. Sharing shows an indicator in game and
can be stopped from Advanced & Tools at any time. Abuse-bounded: 300 lines/min and
10 MB per player, lines truncated at 400 chars, files pruned after 14 days,
folder excluded from backups.

Living world - on by default since v1.2.0
-----------------------------------------
World events and global quests run by themselves so the server feels alive
without any owner setup. Config/World.json has two blocks, Events and
WorldQuests, and every duration in it is in minutes:
  - World events auto-roll: considered every 4h with a 40% chance (~one event
    per 10h on average, so timing feels organic, not scheduled), lasting 3h by
    default (Events.RollEveryMinutes, Events.RollChance, Events.DefaultMinutes).
    Types: tax holiday, market boom/crash, resource shortage, double worker XP,
    house stipend, bounty target, global weather - Events.AllowedTypes and
    Events.Weights are yours to tune.
  - Global weather: a rolled event applies a real GameCondition (aurora,
    eclipse, cold snap, heat wave by default) to EVERY colony for the duration.
    Fully data-driven via Events.Weather.ConditionDefs entries of
    "GameConditionDef|Title|Description" - add any vanilla or modded condition
    def, no code needed. Fire one manually: kmh event world_weather [minutes]
    [0] [DefName].
  - Global quests auto-generate: considered every 12h, up to 2 active, each
    running 48h by default (WorldQuests.AutoGen.EveryMinutes, AutoGen.MaxActive,
    AutoGen.DefaultMinutes, kept between AutoGen.MinMinutes and MaxMinutes -
    24h to 72h). Rewards come from the house pool (seeded once on new servers),
    scale with the live economy, and are floored and capped (WorldQuests.Rewards.Min
    and Rewards.Max). When the pool cannot cover the floor, Rewards.AllowMinted
    (on by default) adds only the shortfall; set it false for pool-only rewards.
  - Everything announces once in-game and (if configured) to the Discord
    Announcements channel when it fires/completes - no periodic spam.

  - Generated content: by default 60% of auto-generated quests are synthesized
    from YOUR server's live item catalog (items + prices reported by clients) -
    "Shortage: cloth", "Supply Run: steel" - instead of the premade templates.
    Tune with AutoGen.FromCatalogPercent (0 = templates only), the per-unit value
    band (AutoGen.CatalogItemMinValue and CatalogItemMaxValue) and
    AutoGen.CatalogGoalValue.
  - Global-quest balance: hunt/build goals SCALE with active players so a quiet
    server isn't asked for 58 kills. goal = clamp(Scaling.BaseTargetCount +
    activePlayers * Scaling.TargetsPerActivePlayer * Scaling.DifficultyMultiplier / hardness,
    Scaling.MinTargetCount, Scaling.MaxTargetCount), all under WorldQuests, where hardness is
    1.5 for big or dangerous game (thrumbo, bear, mechs), 1.25 for large livestock and 0.75
    for small game, so a hunt asks for fewer of the animals that are harder to find. Active
    players are everyone online plus everyone seen within Scaling.ActivityWindowMinutes
    (2880 = 48h), never fewer than are online now; set Scaling.OnlinePlayersOnly=true
    to count only who is connected, or Scaling.ByActivePlayers=false for the old fixed
    goal between AutoGen.GoalMin and GoalMax. Auto-gen is skipped below
    Scaling.MinActivePlayers, and the same target isn't reused within
    AutoGen.RepeatCooldownMinutes. The reward adds Rewards.PerTarget per goal unit;
    co-op payout is split BY CONTRIBUTION (you earned 12 of 58 -> ~12/58 of the
    pool). Kill counting: a direct kill counts ONCE, and a target that bleeds out
    after recent colonist damage counts (predator/weather deaths don't).
  - Weather can be auto-discovered too: clients report every GameConditionDef in
    their game (mods included) into Catalog/WeatherDefs.json; set
    Events.Weather.AutoDiscover=true to roll those as well
    (Events.Weather.ExcludedDefs blocks colony-wreckers like toxic fallout -
    extend it for harsh modded conditions).

How quests verify themselves (no admin approval needed):
  - hunt:    the client counts kills of the target def (persistent tally, saved
             with the game) and auto-reports progress every ~4s; only kills made
             AFTER the quest went live count.
  - build:   the client counts standing player-faction structures of the target
             def and auto-reports growth; pre-existing buildings never count.
  - deliver: players click Deliver on the quest board and the goods are taken
             from their KMH treasury, so the server only ever counts goods it
             actually holds. Only what the objective still needs is taken; the
             rest stays in the treasury.
  Hunt and build progress is the client's own count, so those quests still run
  and announce but pay nothing unless you set WorldQuests.PayForSelfReported=true.
  Progress reports are cumulative and resend-safe (the server keeps each
  player's max), and world snapshots are pushed to every connected player on
  change - nobody has to open a menu for their progress to count.

Per-item control (keep some, disable others) - all in Config/World.json:
  - One event type:      remove it from Events.AllowedTypes, or set its entry in
                         Events.Weights to 0 to stop auto-rolls but keep manual
                         firing.
  - One weather kind:    remove its line from Events.Weather.ConditionDefs (and
                         add its defName to Events.Weather.ExcludedDefs if
                         discovery is on).
  - One quest objective: remove hunt/build/deliver from WorldQuests.AllowedObjectives.
  - One quest template:  delete its line from WorldQuests.Templates.
  - Generated quests:    AutoGen.FromCatalogPercent=0.
Quieter server overall? Set Events.AutoRoll=false and/or
WorldQuests.AutoGen.Enabled=false (manual `kmh event` / `kmh worldquest` still
work), or turn the whole system off with LivingWorld=false in Config/Features.json.

Updating from an older release: v1.3.1 regenerates World.json (with every other
tunable config) from these defaults once - see "Updating to 1.3.1" above.

Frontier, sites & roadworks - new in v1.3.0
--------------------------------------------
Sites gained an archetype, a condition, buildings, and a server-side director
that opens objectives on the world map without you scheduling anything.

  - Archetypes (Config/Sites.json): Farmland, Quarry, Woodland, Ranch,
    Roadworks or Custom. The archetype names the site and decides which colonist
    skill its work uses; matching it to what the site produces earns a small
    specialization bonus. Custom takes none. Sites that existed before the
    upgrade read as Custom and keep producing exactly what they produced.
  - Buildings & storage: 2/3/4 slots by tier. Production raises output, housing
    raises the worker cap, storage lets a site hold output for collection instead
    of delivering every cycle. Held goods are the owner's OFF-MAP WEALTH - they
    count toward raid scaling and do not survive an economy reset. Only the owner
    can store at their own site; overflow always falls through to the treasury.
    Demolishing refunds nothing, so a building can never be used to park value.
  - Condition: a damaged site produces less but never nothing (output flattens
    to a floor). There is NO decay and NO upkeep chore - nothing lowers condition
    on its own. Damage comes from `kmh site-condition damage <tile>` or an
    extension; owners repair from the site's building window, priced on the damage
    actually undone.
  - Roadworks: a Construction archetype that lays persistent roads - Trail, Road,
    Highway, each unlocked by site tier. Priced per NEW segment, so crossing an
    existing road costs nothing. Silver is held while a project runs and returned
    for whatever is unbuilt if cancelled; finished road stays. Reserved silver
    counts toward raid scaling and is destroyed by an economy reset, so a project
    cannot hide wealth. Turn the system off with AllowRoadworks=false in
    Config/Sites.json. Inspect and rescue with `kmh roadworks`.
  - Frontier Operations (Config/Frontier.json): a director opens objectives -
    the first is Reclaim, restoring a derelict ruin - and hands the restored
    location to whoever contributed most, earliest. The winner chooses at claim
    time whether it becomes theirs or their guild's. Funded ENTIRELY from the
    house pool: the advertised reward is capped to what the pool can back and the
    operation does not open if that falls below the configured minimum. Nothing
    is ever minted to cover a shortfall.
    Locations are placed by asking connected clients for candidate tiles;
    matching answers from independent clients are stronger corroboration. Set
    AllowSingleProposer=false if you want that corroboration required - by
    default a small server may act on one valid proposal. Either way the server
    decides, and proposing costs and pays nothing.
    Frontier is ON by default and bounded by its spawn budget, cooldowns and
    active-location limits rather than by an off switch. Owner tooling is
    `kmh frontier` - inspect the director, list outposts, place one, step it, or
    claim on a player's behalf (refused unless that player actually earned it, so
    it settles disputes without handing anything out).
  - A captured location arrives as infrastructure, not a finished site: its new
    owner picks what it produces once, through the normal output rules and with
    no build cost. A location nobody claims goes dormant and is reused by a later
    operation instead of holding its tile forever.
  - Guild-owned sites: any current member can assign workers, build, repair,
    collect storage and set up a captured location. Leaving the guild removes
    that access at once. Production is guild income - it goes to site storage or
    the guild vault, never through whichever member opened the menu, and it does
    not inflate anyone's contribution standing. A road project stays personal to
    whoever started it: they pay, they can cancel, their escrow returns to them.

Communications - chat, mail & presence - new in v1.3.0
-------------------------------------------------------
  - KMH chat (Config/Chat.json): server-wide, per-guild and direct-message
    channels, with history on reconnect, per-user rate limits and a server-side
    log of every message.
  - Player mail (Config/Mail.json): letters carrying silver, items or
    full-condition gear. Attachments are escrowed server-side, can be recalled
    while unread, and are returned automatically if never claimed - a letter to
    someone who never logs in again cannot eat what it carried. An optional
    per-letter fee is off by default.
  - Moderation: per-player block lists filter live messages AND history, and
    staff can remove messages. A block also applies to mail.
  - Presence & playtime: the server measures time connected and, separately,
    time actually played - a paused game nobody has touched for two minutes stops
    counting, watching a raid does not. Both feed the Activity Records standings
    board and Discord's `/kmh leaderboard active`. The roster keeps whoever was
    here most recently, so a busy server stops hiding half its players.
  - Staff badges & colours (Config/Staff.json): owners, admins, moderators and
    developers are marked from YOUR role list, never from anything a client
    claims. Name, message and relay colours are per-server, and the text always
    carries the same meaning as the colour.
  - Discord chat bridge: mirrors KMH chat to a channel in either direction, each
    side independently configurable. Linked accounts post under their verified
    in-game name; a relayed message can never masquerade as native chat.

Chat image previews
-------------------
On for a new server. A preview only ever loads from a host on
ImageHostAllowList in Config/Chat.json - Discord's CDN, Tenor, Giphy and Imgur
ship in that list - and only when the player clicks to load it, so nothing
reaches out on its own. Turn the whole thing off with AllowImagePreviews: false.

v1.3.1 REGENERATES Chat.json from defaults rather than keeping your value, so
image previews come back on unless you turn them off again afterwards. Your
previous file is in the premigration-config backup under KMH-Data-Backups.

Two separate lists, because two different machines make the request:

  Chat.json    ImageHostAllowList   where a PLAYER's game may load an image from
  Media.json   SourceHostAllowList  where the SERVER may fetch one to convert

Both ship the same starting set. Leaving SourceHostAllowList empty means "any
https host" for the server's own fetch - still https-only, still refused for
any private or loopback address, still re-checked on every redirect, but wide.
A new server gets the list rather than the blank, so widen it deliberately if
you need to rather than starting there.

In-game video - optional, off until you add two tools
-----------------------------------------------------
Players can watch a video link without leaving the game. Your server resolves
the link, pulls it down once as a finished mp4, keeps it in KMH-Data/MediaCache
and serves that file itself. Clients only ever talk to you, never to the video
host, and the Workshop mod carries no downloader at all - which is what keeps it
Workshop-safe.

Two programs do the work and KMH does not ship them:

    yt-dlp    resolves the link
    ffmpeg    turns it into something the game can play

Miss either and the video server stays off; the boot log names the missing one.
Everything else runs as normal. They belong to other people under other
licences, so KMH fetches them for you instead of redistributing them.

The fetch script comes with the server, in the Tools folder beside
KMHServerAddon. Run it there:

    Windows   .\Tools\get-media-tools.ps1
    Linux     ./Tools/get-media-tools.sh

Both binaries land in that same Tools folder, which is where KMH looks. Setting
this up on a machine that has no server on it? The same two scripts are also
published on their own as KMH-MediaTools-v<version>.zip.

Restart afterwards and look for "Video server: using yt-dlp.exe" and "using
ffmpeg.exe". No config edit either way. KMH checks these, beside the executable
and then again inside KMH-Data: the folder itself; Tools, plus any folder inside
Tools and that folder's bin; bin; and any <folder>/bin. Unzip an ffmpeg archive
straight into Tools and it will be found - no need to dig the binary out. Point
at copies you already have with Video.HelperPath and Video.FfmpegPath in
Config/Media.json.

POINTING AT YOUR OWN COPY. Both settings take the FULL PATH TO THE EXECUTABLE -
the file, including yt-dlp.exe, not the folder it sits in. JSON also treats a
backslash as an escape character, so every one has to be doubled. Both sit in
the "Video" block:

    "Video": {
      "HelperPath": "C:\\Program Files\\GameServer\\ToolsForKMH-Patch\\yt-dlp.exe",
      "FfmpegPath": "C:\\Program Files\\GameServer\\ToolsForKMH-Patch\\ffmpeg.exe",
      ...
    }

Leave either blank to use the automatic search above; that is the normal case
and nothing is lost by it. If you do set one and it is wrong - a folder instead
of the file, a typo, a drive that is not mounted - the boot log says which of
those it was, then falls back to searching. It does not fail the server, and it
does not go quiet either.

Relative paths resolve against whatever folder the server was started from, which
is not always the folder it lives in. Use a full path.

SEVERAL SERVERS, ONE COPY OF THE TOOLS. Supported, and nothing needs to be
duplicated: KMH only ever runs these programs, so any number of KMH or RimWorld
Together servers can point at the same yt-dlp.exe and ffmpeg.exe. Downloaded
video and converted images stay per-server in that server's own
KMH-Data/MediaCache, so they never collide. What each server does need is its own
copy of the PATH SETTING - they are per-server config files.

NO INTERNET ON THE SERVER? Common on a locked-down host, and not a problem. Run
the script on a machine that has internet, tell it which platform you are
fetching for ('.\get-media-tools.ps1 -Rid linux-arm64'), and move the Tools
folder across however you normally move files. Nothing reaches out again once
the binaries are there.

Watch out for one thing: nobody builds a current 32-bit Windows ffmpeg any more,
so win-x86 gets yt-dlp and the video server stays off.

Ports: video is served over the KMH transport port and nothing else. KMH opens
exactly one port, ever - the one in KmhApiPort. There is nothing extra to open,
and no setting that would ask you to.

Config (KMH-Data/Config/)
-------------------------
  Economy.json          marketplace/auction/want tax, caps, price floors. Deposits are
                        client-trusted, so Treasury.MaxSilverDepositPerTx (1,000,000) and
                        Treasury.MaxItemDepositQtyPerTx (5,000) reject an absurd single
                        deposit (anti-mint). Keep them generous - the client removes the
                        goods before sending, so a legit deposit at or under the cap must
                        never be rejected. 0 disables a cap.

                        ANTI-CHEAT (the AntiCheat block). A client decides what its colony
                        holds, so a memory editor such as Cheat Engine can create goods.
                        These bound what one account can bank, not the cheat itself:
                          AntiCheat.DailyDepositLimit (200,000) - silver-equivalent value
                            one account may deposit in any 24 hours.
                          AntiCheat.NewPlayerDailyDepositLimit (25,000) - the same for an
                            account with fewer than AntiCheat.NewPlayerHours (10) hours
                            connected this season, as the server measures it.
                          AntiCheat.AlertStaff (true) - limit hits and freezes also go to
                            the Discord admin channel; they are always logged.
                        0 turns a limit off. A deposit past the limit is refused before
                        anything leaves the colony. Items count at their catalog value
                        ('kmh catalog <def> <silver>' pins one); an item with no value
                        counts 10 each. Simulated accounts are never limited.
                        Staff: 'kmh deposit-limit <user> [extra] [hours]' shows an
                        account's room or raises it for a while; 'kmh freeze <user>
                        [reason]' stops its deposits, trades and transfers (chat and
                        reports still work), takes it off the boards and pauses its
                        listings and auctions; 'kmh freeze <user> undo dry|confirm' takes
                        back its guild donations still in guild vaults and runs
                        wipe-economy; 'kmh unfreeze <user>' and 'kmh frozen'.

                        Treasury.AccessFeeSilver (default 0 = off) is a flat charge to
                        OPEN a treasury session, not a per-transaction fee: one debit
                        buys ten minutes, and refreshing, reconnecting or reopening the
                        window inside that time costs nothing. Taken from the vault being
                        opened, and waived while that vault is empty. Site/office
                        discounts do not apply - this prices access, not a trade.

                        ECONOMY / TREASURY ACCESS MODES. EconomyMode is generated as
                        Balanced (v1.3.1 regenerates it too). EconomyMode is a preset:
                          Standard  - remote treasury, no cooldowns/fees/caps.
                          Balanced  - remote, light 5s cooldowns + 1% deposit/withdraw fee
                                      (the generated default).
                          Localized - personal treasury at your colony, guild vault at a
                                      guild hall, item moves need a caravan, treasury
                                      blocked during raids, 5s cooldowns, no fees.
                          Hardcore  - CaravanOnly, block during raids AND hostile map events,
                                      10s cooldowns + 2% fees.
                          Custom    - uses the granular fields below verbatim.
                        Granular fields, in the Custom block (used only when
                        EconomyMode=Custom):
                          Custom.PersonalAccess = Remote | ColonyOnly | CaravanOnly |
                                                  Disabled
                            (TreasurySiteRequired is reserved - Treasury Sites do not
                             exist yet, so it is accepted but not enforced and behaves
                             as Remote. The server warns once at boot if you set it.)
                          Custom.GuildAccess    = Remote | GuildHallRequired |
                                                  CaravanNearGuildHall | Disabled
                          Custom.DepositCooldownSeconds / WithdrawCooldownSeconds (0 = none)
                          Custom.DepositFeePercent / WithdrawFeePercent (0..50; silver-only
                            service fee -> the house pool, same sink as marketplace
                            tax. Deposit fee credits only when the pending deposit
                            commits; withdraw fee on success. Item deposits/withdraws
                            pay no fee. Balanced=1/1, Hardcore=2/2, others 0.)
                          Custom.MaxPersonalSilver / MaxGuildSilver (0 = no cap)
                          Custom.RequireCaravanForItemDeposit / RequireCaravanForItemWithdraw
                          Custom.BlockDuringRaid / BlockDuringHostileMapEvent
                        DisablePersonalTreasury / DisableGuildTreasury switch a treasury
                        off in every mode, Custom or not.
                        The client reports context (colony/caravan/raid/hostile-event/near-
                        guild-hall) with each treasury/guild action; the server enforces per
                        mode. TreasurySiteRequired still fails gracefully (behaves as Remote +
                        one-time warning) since Treasury Sites aren't built yet. Pending
                        (unconfirmed) deposits stay non-spendable regardless of mode. The boot
                        banner + 'kmh audit' show the active policy.

                        PASSIVE INCOME vs ACCESS MODES: access modes gate PLAYER-INITIATED
                        deposits/withdraws only. Earned/returned value - site rewards, and
                        marketplace / auction / want payouts and refunds - is deposited directly
                        and still accrues into the vault under any mode. Under a restrictive mode
                        the player simply can't WITHDRAW it until they meet the access rule; under
                        Disabled it accrues but stays locked until you re-enable access. This is
                        intentional (earned value is never dropped); 'kmh validate configs' prints
                        an [INFO] line whenever a non-Remote mode is set so it's never a surprise.

                        GUILD HALL RULES (ALL disabled by default - standard guilds
                        unchanged). A guild's hall is a world-tile record stored ON the guild
                        (so it can't be orphaned or inherited by a reused name; disband/season
                        reset drop it with the guild). An admin sets it from the Guild Hall
                        dialog ("Set Hall here" = their current colony/caravan tile). Fields,
                        in the GuildHall block:
                          GuildHall.RequireToCreateGuild           (create needs a hall tile)
                          GuildHall.RequireForTreasury             (guild vault needs a hall)
                          GuildHall.RequireForContributions        (contributing needs a hall)
                          GuildHall.AccessRadiusTiles = 10         ("near" = within N tiles)
                          GuildHall.RequireCaravanForContribution
                          GuildHall.RequireMemberNearHallToJoin
                          GuildHall.AllowRemoteInvites = true      (false = invite near the hall)
                        Guild access GuildHallRequired / CaravanNearGuildHall (the Localized and
                        Hardcore presets, or Custom.GuildAccess) enforce via the client's
                        near-hall check.
                        COMPATIBILITY: a guild with NO hall is never blocked by proximity (so
                        pre-P8 guilds keep working); the Require* flags are what force a hall to
                        exist first. Proximity is client-computed against the server-owned hall
                        tile+radius (best available - the standalone server can't do tile math).
                        'kmh audit' lists guilds missing a required hall.
  Sites.json            custom-site pricing, worker XP, cycle rate. Cost + cycle also
                        scale with amount/cycle (client can't fake amount) so an under-
                        reported item value can't buy a cheap high-output site. The server
                        uses its TRUSTED catalog value (not the client's) for build cost and
                        logs suspicious under-reports. Anti-spam caps, in the Limits block:
                        Limits.PerPlayer / PerGuild / ServerWide, Limits.WorkerSitesPerPlayer,
                        Limits.WorkersPerPlayerPerSite, Limits.BuildCooldownMinutes.
                        WORKERS ARE COLONISTS, not accounts (new in v1.3.1): one player
                        can staff a site with several different colonists, up to the
                        site's capacity and Limits.WorkersPerPlayerPerSite (3). More
                        colonists make the site faster and raise its output; the SHARE
                        split stays per player, so this cannot mint anything. Existing
                        sites re-key themselves on first boot and keep their XP. Worker
                        skill from the client is advisory only; server-owned site XP is
                        authoritative. Lower Output.CustomMaxRewardAmount or set
                        AllowCustomSites=false to bound further.

                        OUTPUT TIERS (server-authoritative; Output.UseTiers=true):
                        every output is classified into a tier that decides allow/block, the
                        per-cycle amount cap, cost/cycle multipliers, and how far workers can
                        scale it. Unknown/rare/tech items land in Tier 4
                        (Output.DefaultUnknownTier=4), which ships DISABLED - so a site can
                        NEVER print weapons, apparel, tech/techprints, bionics, ammo, genes,
                        relics, drugs, or minified buildings. Tiers: 1 Basic
                        (wood/raw/hay/meat), 2 Refined (steel/cloth/blocks/meals), 3 Advanced
                        (plasteel/uranium/gold/components), 4 Crafted/Rare/Tech (off). Each
                        tier in Output.Tiers[] has the same fields: Enabled, Name, MaxAmount,
                        CostMultiplier, CycleMultiplier, MaxSpeedMultiplier, MaxOutputMultiplier,
                        AllowAutoClassifiedItems, Allowed/BlockedDefNames, Allowed/BlockedKeywords
                        (Blocked* always win). Output.MaxAllowedTier caps the highest usable
                        tier server-wide.
                        Workers set the speed and skill sets the amount, each capped by the tier
                        (Tier 4 never multiplies output). An over-limit build amount is REJECTED
                        (not silently clamped) and the treasury isn't charged.
                        Workers.AutoAddOwner=true makes the owner count as a worker so a
                        solo/private site produces (0 workers = Paused). To allow a specific
                        extra item, add its defName to a tier's AllowedDefNames; to allow Tier
                        4, set Output.Tiers[3].Enabled=true. There is no payout timer to set:
                        each site's own cycle time (Output.CycleMinutesPerRewardUnit, divided by
                        worker speed) decides when it pays. With Output.UseTiers=false a site
                        falls back to plain stackables only - widen that with
                        Output.ExtraSimpleResourceDefs, or set Output.AllowUnsafeLegacy=true for
                        the old unrestricted all-def behaviour (admin/dev only; the server warns
                        at boot when it is on). Output.FamilyOverrides takes "defName=family"
                        corrections for an item the classifier misreads; 'kmh site-catalog
                        <defName>' shows how one is classified.
  (Treasury items)      Complex items (weapons/apparel/minified/comp/modded) are stored
                        with full state (Treasury.json item_payloads) so a deposit->withdraw
                        round-trip never cleans taint, repairs damage, rerolls quality, or
                        strips material/comp data; clean/tainted and damaged/undamaged stacks
                        never merge. Plain resources stay compact (items map). Items deposited
                        before v1.2.0's payload system load as LEGACY - their exact state can't
                        be proven, so restore-preview flags them and they never silently become
                        clean/full-value.
  Reputation.json       score deltas + tier cutoffs
  Quests.json           per-poster caps, expiry
  World.json            server event + global-quest scheduler / reward tuning
                        (auto-roll + auto-generate ON by default since v1.2.0)
  Features.json         turn major systems on/off (treasury, marketplace, guilds,
                        quests, auctions, want board, world, standings, and Reports -
                        the in-game bug report / suggestion button). All on by
                        default; off blocks that system server-side and clients show
                        it as disabled. Stored data is kept - re-enable to restore it.
  Chat.json             KMH chat: retention, rate limits, blocking, the image/video
                        allow-list and size cap, and the presentation colours + Discord
                        marker that ride the handshake. Presentation only - these never
                        affect permissions, identity, moderation or message contents.
  Media.json            server media resolver: the server converts formats a client
                        cannot decode (animated WebP -> GIF) and serves the result over
                        KMH's own connection. On by default, and only for those formats -
                        png/jpg/gif still load directly. Privacy: a direct load exposes the
                        PLAYER's IP to the host, a resolved one exposes the SERVER's, and
                        neither happens without the player's click-to-load choice. Bounds
                        for source/output size, pixels, frames, decoded memory and timeouts
                        all live here; the outbound fetch is https-only, allow-list checked
                        on every redirect, and refused for any private address.
  Staff.json            who is shown as staff and how the badges look (each role's Label
                        and Color in the Badges block). Admin is not a list
                        to maintain - RWT already knows its admins; list someone under
                        Admins only to badge a person RWT does not consider one.
  Mail.json             player-to-player mail: attachment limits, optional send fee,
                        unclaimed timeout.
  Frontier.json         Frontier Operations director: outpost and operation caps, action
                        pacing, and what a Reclaim asks for and pays. A Reclaim scales with
                        your population: ReclaimScalePerActivePlayer (0.15) adds 15% per
                        player online beyond the first, ReclaimScalePerKnownPlayer (0.05)
                        adds 5% per player who has ever joined, and ReclaimScaleMax (5.0)
                        caps the result. The SAME multiplier is applied to the material
                        cost and the silver reward, so a busy server is a bigger contest
                        rather than a better or worse deal. Set both weights to 0 for the
                        old flat behaviour.
  Enforcement.json      config-enforcement state + safe-mods list
  Maintenance.json      ServerName (this instance's friendly name - set a distinct one
                        per server on a shared host), automatic-backup + boot scan settings,
                        and ConsoleLogLevel - all (default), warn, error or quiet. It only
                        decides what the terminal is shown; KMH-Data/Debug always receives
                        every line, so turning the console down loses nothing.
  Discord/DiscordConfig.json   paste a bot token to enable the Discord bridge, or set the
                        KMH_DISCORD_BOT_TOKEN environment variable instead and leave the
                        field blank - the variable wins, and the config is never rewritten
                        with the secret. Running
                        several bots in one Discord? Set Bot.RequireMention=true so each
                        only answers !kmh-* text commands that @mention it (e.g.
                        "@KMH-25554 !kmh-link CODE") - otherwise all of them reply. Slash
                        commands are already per-bot. DMs still work without a mention.
                        Set Roles.SyncGuildRoles=true to give linked players a Discord role
                        named "<Guild> (<Rank>)" that tracks their KMH guild + rank (needs
                        the bot to have Manage Roles + its role above the ones it creates).
                        Nothing is posted as an embed. Channels.Leaderboard gets one image per
                        board per day (Live.LeaderboardBoards, default auto + guilds), edited
                        every Live.LeaderboardEveryMinutes=15 and finished when the day turns
                        over at Live.DayStartsAtUtcHour=0 (UTC). Channels.Marketplace gets a
                        live market board (Live.MarketBoardEveryMinutes=10, 0 = off) and, with
                        Channels.SiteEvents and Channels.Announcements, a daily activity log of
                        one line per event. Channels.Admin gets a live server status
                        (Events.Status) and plain-text alerts (Events.Alerts); set
                        Events.AlertsPingModerators=true to mention Roles.Moderators in them.
  Federation.json       Guild Federation on this server: Benefits, the ceilings
                        MaxSiteOutputBonusPercent / MaxRoadworksBonusPercent (3, and never
                        higher), ObjectiveRewards and RewardScale for the local supply
                        caches, and ReportContributions.
  Mods.json             which mods RWT already lists are Required or Optional, and
                        ExpansionsOptional. Anything outside that list is refused by RWT.
                        RimWorldVersion is the RimWorld version this world is played on:
                        1.7 on RimWorld Together 26.10.20.1 and later (it admits only 1.7,
                        so a lower value there is read as 1.7), 1.6 before. It is listed
                        on Global, and a player on another version is refused at join.
  Global.json           Colony Nexus Global: Enabled (off until 'kmh global setup'),
                        BackendIdentity (the private identity Guild Federation uses, on),
                        Visibility, PublicHost, AllowOperatorConsole (off), ForwardReports
                        (off: player reports stay on this server; 'kmh reports forward on'
                        sends new ones to Global too), and the Listing block - what players
                        see on Colony Nexus: Description, Tagline, Region, Languages, Tags,
                        PlayStyle (PvE/PvP/PvPvE), NewPlayersWelcome, Whitelist + ApplyUrl,
                        RulesUrl, DiscordUrl, WebsiteUrl, WorkshopCollection, Announcement,
                        MaintenanceMessage + MaintenanceUntilUtc. Every Listing field is
                        optional; links must be https. Never regenerated. What Global
                        assigned (the server id, generation and heartbeat sequence) lives in
                        KMH-Data/Identity/global-state.json, not here.
  (Transport and Discord have their own on/off switch in their files above.)
All are generated with defaults on first boot, and a later update tops each file up
with any field it added, keeping every value already set. When a release moves a
setting (rel-274 grouped Global's listing, Transport's limits and the staff badges),
your value moves with it and 'kmh migration-report' lists each move.
Not sure everything is right? Run  kmh doctor  : every health check in one list,
worst first, each with what to do about it. Boot ends with a one-line summary. The one exception is the
first boot of v1.3.1 itself, which regenerates the tunable files (see "Updating to
1.3.1"). Reload config live (in-game chat or server console):  kmh reload <area|all>
`kmh config` lists what you have changed from the shipped defaults, per area; for
economy it also prints the policy actually IN FORCE, because the granular fee,
cooldown, cap and raid fields apply only under EconomyMode=Custom.
(The older reload-economy / reload-world / ... commands still work.)

Player reports - new in v1.3.1
------------------------------
Players can send a bug report or a suggestion from the Colony Nexus tab, from
Advanced & tools, or from a "Report this problem" button on a KMH window that
failed to draw. They see the screenshot and the diagnostics before anything is
sent, and the window tells them who received it. Each report is kept on this
server in KMH-Data/Reports (the newest 300, for 90 days):
  kmh reports                     list them, newest first
  kmh reports show <id>           read one (the first four letters of the id are enough)
  kmh reports delete <id>         remove one from this server
  kmh reports forward <on|off>    also send new reports to Colony Nexus Global, where the
                                  KMH developers read them (off by default; it sets
                                  ForwardReports in Global.json). The copy Global gets keeps only the
                                  console's warnings, errors and the reporter's own lines.
  kmh reports retry               send kept or failed reports to Global again
Players are limited to 3 reports in 10 minutes and 15 a day. Turn the button off
entirely with Reports=false in Config/Features.json. 'kmh setup info' describes
exactly which report fields Global would receive.

Performance
-----------
  kmh perf                frames and bytes sent and received, compression saved,
                          send queues, slow players dropped, scheduler jobs, memory
A player who stops reading no longer slows anyone else down: each connection has
its own send queue, and one that falls 8 MB behind is dropped (the game
reconnects on its own). Players see their own frame rate, game speed and what
KMH costs each frame under Advanced & tools.

Backups & recovery
------------------
KMH backs up KMH-Data/ on every boot (into a sibling KMH-Data-Backups/ folder)
and scans it for problems at startup. Owner commands (console or /kmh server):
  kmh verify              read-only integrity scan
  kmh backup [reason]     snapshot KMH-Data now    |  kmh backups   list them
  kmh restore <name|latest|before:<time>>   roll KMH-Data back to a backup (owner or console only;
                          the live bans, network bans and economy freezes are kept, so rolling
                          back a cheat never lifts the ban that followed it)
  kmh inspect <system>    dump auctions/wants/quests/... with ids
  kmh cancel <auction|want|quest> <id>   refund + remove a stuck entry
  kmh ledger [user]       recent economy audit-trail entries
  kmh smoketest           non-mutating live health check of every subsystem
  kmh support-bundle      writes KMH-Data/Support/kmh-support-<stamp>.zip: configs, the
                          status file, the latest migration report and the tail of the
                          system log, all passed through KMH's redaction (bot tokens, API
                          tokens, webhooks, passwords and signed-url signatures are masked).
                          No binaries, backups, saves, media cache or chat history. Review
                          it before sharing if you like - it is plain text inside.

Rolling back with RWT
---------------------
KMH-Data lives beside RWT's saves, not inside them, so an RWT world rollback
leaves KMH (treasury, sites, marketplace) reflecting the newer state. Bring KMH
along with a restore. It's applied at the NEXT startup - before anything loads -
and always safety-backs up current KMH-Data first, so it stays reversible.
  - By hand:  kmh restore before:<time>   then restart the server.
  - From tooling: write the target into KMH-Data-Backups/.kmh-restore-request
    (one line: a backup folder name, "latest", or "before:<iso|yyyyMMdd-HHmmss>")
    and restart. KMH consumes the marker on boot.
Pair it with an RWT rollback by matching the timestamp: KMH's boot backups are
named yyyyMMdd-HHmmss (UTC), and "before:<RWT-snapshot-time>" picks the newest
KMH backup at or before that moment. Set BackupOnBoot=true (Config/Maintenance)
so there's always a recent snapshot to land on; raise BackupRetention to keep
more history for deeper rollbacks.

Monitoring & external tooling
-----------------------------
KMH writes a machine-readable snapshot to KMH-Data/status.json on boot, every
~60s, and on demand (kmh export). It's a stable JSON contract for dashboards,
leaderboards, and health checks - read it instead of scraping internal data
files. It carries ServerName + a stable ServerId + the KMH ApiPort (so you can tell
several instances on one host apart and map bot<->server<->port), build/wire
versions, uptime, live counts (players, guilds,
marketplace/auctions/wants/quests/sites, active events + global quests), house
pool + reported wealth, current season, disabled features, the current-season
leaderboard toppers (player, colony, trade, guild, and treasury under Leaders),
and the backup list (name + UTC) for rollback correlation. Because it's rewritten
on a cadence, a
stale GeneratedUtc / file mtime means KMH has stopped - use it as a heartbeat.

Seasons
-------
  kmh season          show the current season
  kmh season roll     archive this season's leaders + all-time records, advance
                      the counter. Non-destructive - lifetime stats stay.
  kmh season reset confirm   archive leaders, THEN wipe the live economy for a
                      fresh season: treasury (personal + guild vaults), market +
                      house pool, auctions, want board, sites, quests, reputation,
                      pending mail, world events + global quests, and standings.
                      Guilds (membership + perks), Discord links, and the season
                      archive are KEPT. Backs up first, so it's reversible with
                      'kmh restore <that backup>'.
The 'confirm' word is required (it's a full economy wipe), and only the owner (Staff.json
Owners) or the server console can run it. Deliveries already owed to colonies are kept:
those goods left KMH before the reset. Pair reset with a fresh RWT scenario at season
start so colony wealth also begins near zero.

Anti-cheat & enforcement
------------------------
Config enforcement (Enforcement.json): with both the addon and the KMH Patch
installed you can lock players' Mod Options to a profile you supply and keep a
safe-mods list. Turn it on with 'kmh enforce on'. This needs the patch on the
client - stock RWT clients can't be enforced.

Scenario / custom-scenario enforcement is NOT implemented yet. KMH can't force a
required scenario or block custom scenarios in v1.3.1 either; treat it as planned.
Until then, agree a scenario out-of-band and watch for odd starting wealth.

Save-reset economy: KMH-Data outlives a player's RimWorld save, so someone can
deposit starting resources into their treasury, reset their save, and repeat.
  - Automatic: set ResetEconomyOnNewSave=true in Config/Economy.json (off by default).
    When a player's colony reports a new save id, KMH runs the same economy reset
    as wipe-economy below. The save id comes from the client, so treat it as
    evidence, not proof: a modified client can claim a new save (at most one reset
    per player per 6 hours) or hide one.
  - Manual (all take 'dry' or 'confirm', back up KMH-Data first and say what they did):
      kmh reset-preview <user>             what a reset would clear (read-only)
      kmh wipe-economy <user> <dry|confirm>   (alias reset-player-economy) the economy only
      kmh treasury-reset <user> <dry|confirm> the same as wipe-economy
      kmh treasury-reset all <dry|confirm>    every personal vault and nothing else (owner/console)
      kmh wipe-player <user> <dry|confirm>    the economy plus mailbox, guild membership,
                                              standings, reputation, notices and Discord link
      kmh reset-cleanup <user> <dry|confirm>  audit, wipe-economy, then rebuild standings
What a reset clears for that player: the personal treasury and a solo guild's vault;
their listings, auctions, leading bids, want posts, quest bounties, mail attachments
and roadworks escrow (burned, not refunded); owned sites and worker slots; recovery
records; deliveries owed to the old colony; and payouts or refunds written down but
not yet paid. Other players are made whole: bids on the player's auctions, attachments
others sent them, and the other side of any unfinished trade are returned or finished,
and a delivery quest whose goods already reached a reset poster pays its claimer.
A guild Owner removed by wipe-player passes the guild to its senior member first.
Kept: the username, guild membership (except wipe-player), donations already in a
multi-member guild vault, the ledger history, and anything already paid to others.
A reset is written down step by step: a crash or a full disk pauses the economy
and the reset finishes on the next retry or boot, never twice. Nothing reports it
done until every step is saved. RimWorld Together's own player reset does not run
a Colony Nexus reset - run wipe-economy too. Run 'kmh audit' to spot orphaned or
solo-guild vaults. 'kmh maintenance off' only lifts a 'kmh maintenance on'; a hold
a reset or restore owns lifts when that finishes.

KMH Global - linking, and unlinking
-----------------------------------
'kmh global setup' at the server console links this server to your KMH account
and lists it in the in-game server browser. Three commands undo that, and they
do different things:

  kmh global disable          A PAUSE. Stops heartbeating, so the listing drops
                              out of the browser. Keeps the server id, the
                              signing key and the registration. 'kmh global
                              setup' is not needed to come back - re-enable and
                              it resumes where it left off.

  kmh global unlink confirm   A LOCAL FORGET. This installation forgets its
                              registration and owner link. It keeps the server id
                              and the signing key, because Global knows the server
                              by them, and it does NOT revoke anything on Global.
                              Afterwards 'kmh global setup' links this same
                              identity again.

  Revoke, from the owner panel in your browser
                              ENDS THE REGISTRATION on Global, for good. The key
                              stops authenticating anywhere, the listing is gone,
                              the server's guilds leave their federations, and the
                              id can never be registered again.
                              Deliberately not a console command: a machine that
                              has lost its key, or someone who has taken a copy
                              of it, must not be able to end your registration.

'kmh global status' shows both sides - what this server holds, and what Global
says about it. That second line is the one that tells a revoked registration
apart from a network problem.

KMH Global - changing the signing key
-------------------------------------
KMH-Data/Identity holds the key Global knows this server by. Back it up with
your saves: restoring a newer copy is always the simplest fix. When that is not
possible, three commands change the key and keep the server id:

  kmh global rotate           Replaces a key that still works - after a
                              suspected leak, say. Shows what will happen;
                              'kmh global rotate confirm' starts it.
  kmh global recover          Replaces a key you no longer have, or one Global
                              refuses (KMH-SRV-303, 309 or 317). Shows what will
                              happen; 'kmh global recover confirm' starts it.
  kmh global rebind <code>    For a server with no owner whose id another key
                              holds, or that the operator revoked. Ask the
                              Colony Nexus Global operator for a rebind code;
                              read them the key this prints before they apply it.

rotate and recover print a link and a code; approve it in your browser, signed
in with Steam as this server's owner, and the server finishes on its own, even
across a restart. The new key is saved before Global is asked and installed only
after Global accepted it; the old one is kept as global-signing.previous.key.
'kmh global <command> cancel' abandons a change that has not reached Global.

Afterwards each federated guild needs an officer (Admin or Owner rank) to press
"Prove this server's link again" in its Federation window.

An owner's own revocation is final: no command and no operator can bring that
server id back.

Build from source
-----------------
Build the target RWT server once, point Source/Local.props or
$env:RwtServerBuildPath at its build output (for the compile-time references),
then run:  .\deploy.ps1   -> Deploy\ folder + zip in Releases\.

deploy.ps1 without -SelfContained produces the framework-dependent layout: one
KMHServerAddon.exe with the payloads, Newtonsoft, Harmony and the SDK inside it.
With -SelfContained it produces a folder instead - .NET 10 alongside a launcher
stub and KMHServerAddon.dll, which is why that zip has to be kept together.
